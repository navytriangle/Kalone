## 지금 가장 중요한 질문

> 복사 좌표를 잘 고르는 것을 넘어서, **실제 언어에서 무엇을 복사할지 올바르게 판단**하는가? 그리고 긴 입력에서 출력 비용이 실제로 얼마나 줄어드는가?

## A. 평가 (먼저 하면 좋음)

- [ ] 🌱 **길이 일반화 평가**: 학습보다 긴 문장(단어 7~20개)으로 평가하는 `evaluate` 옵션 추가
- [ ] 🌱 **비용 측정 스크립트**: 문제별 `출력 문자 수 / 디코더 스텝 수`를 모아 절감률 리포트 출력
- [ ] **오류 분석**: 틀린 경우를 "좌표 오류 / 타입 오류 / 문자 오류"로 분류해 보고
- [ ] 학습에 없던 과제로 평가하는 **제로샷 과제 분할**(hold-out task)

## B. 과제 확장

- [ ] 🌱 새 합성 과제 추가 (swap, 단어 이동, 두 곳 동시 수정, 순서 뒤집기 등)
- [ ] **복사와 생성이 섞인 과제**: 복사한 단어 뒤에 모델이 새 문장을 이어 쓰는 경우
- [ ] **여러 문서에서 복사**: 입력이 2개 이상의 문서일 때 어느 문서에서 가져올지 고르기
- [ ] 코드 편집 과제 (함수 한 줄 수정, 임포트 추가)
- [ ] 🌱 **한글 지원**: `vocab.py`에 한글 음절/자모 추가, 한글 합성 과제

## C. 모델

- [ ] **토큰 단위** 입력/출력으로 확장 (BPE 등)
- [ ] **트랜스포머 인코더/디코더** 버전 (`CopyLM` 인터페이스 유지)
- [ ] 복사 구간 요약을 평균 말고 다른 방식(어텐션 풀링 등)으로 비교
- [ ] 한 구간만 가리키지 않고 **여러 구간을 한 행동으로** 붙이는 변형
- [ ] 복사 **끝 좌표** 대신 **길이** 로 예측하는 변형 비교

## D. 안전장치 (연구 범위 안에서)

- [ ] **복사 범위 제한**: 사용자가 허용한 구간 밖은 `COPY` 불가하게 하는 마스킹
- [ ] **출처 표기**: 출력의 각 글자가 `COPY`인지 `GEN`인지, 어느 구간에서 왔는지 기록하는 provenance 로그
- [ ] **인젝션 실험**: 입력 안의 지시문이 그대로 복사돼 출력되는 사례 정리
- [ ] 좌표를 잘못 짚어 "엉뚱한 구간이 정확히 복사"되는 오류를 사람이 잡기 쉽게 하는 시각화
